### 3. Paquete atribuible al SHA — `git archive`, no copia del working tree

Herramienta nueva: `scripts/c06_construir_paquete.py` (en este worktree).
Construye el paquete desde `git archive --format=tar <SHA>` (nunca del
directorio de trabajo), aplica una lista explícita de exclusiones sobre lo
que SÍ está trackeado en git pero no debe viajar a un cliente, copia el
wheelhouse, escribe el manifiesto y comprime.

**Por qué `git archive` y no copiar carpetas:** un archivo commiteado por
error (ver hallazgo abajo) viajaría igual si se copiara el árbol a mano.
`git archive` sobre el SHA fijo da un paquete bit-a-bit atribuible a ese
commit, y dentro de él una segunda pasada (`verificar_sin_prohibidos`)
vuelve a escanear el árbol final en disco buscando patrones prohibidos
(`.env`, `.sqlite3`, `.dump`, `.bak`, `.pgpass`, `env_cliente.env`,
`env_cliente.bat`) — no confía solo en `.gitignore` ni en la lista de
exclusiones.

```powershell
python scripts\c06_construir_paquete.py `
  --repo <worktree> --sha 9e6fb99621c02275f231124e39b81eed83acd767 `
  --wheelhouse <lab>\wheelhouse\windows-py311 --lab <lab> `
  --portal-ref-branch integration/cierre-prod-C04-admin `
  --portal-ref-sha 4ff424710b1634301783baddd3608ea50a25459c
```

Resultado: `pos_fifo_system_C06.1_9e6fb99621c0.zip` (37.160.669 bytes, 1046
entradas incluyendo los 36 wheels) + su manifiesto JSON. SHA-256 del ZIP en
el manifiesto (ver "Artefactos").
