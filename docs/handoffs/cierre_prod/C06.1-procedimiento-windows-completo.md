### 2. Ni `preparar_paquete.bat` ni `actualizar.bat` conocían el wheelhouse offline

Todo el trabajo de C06.1 (wheelhouse, `pip install --no-index --require-hashes`)
nunca se conectó con las herramientas reales que usa un operador:
`preparar_paquete.bat` (construye `dist\`) no descargaba ningún wheelhouse, y
`actualizar.bat` FASE 4 hacía `pip install -r requirements.txt` liso — **un
paquete "offline" en teoría seguía dependiendo de internet en el momento real
de actualizar**.

**Corrección:**
- `preparar_paquete.bat` ahora tiene un paso `[3b/5]` que corre
  `pip download --require-hashes --only-binary=:all:` hacia
  `dist\pos_fifo_system\wheelhouse\windows-py311` — usa el mismo comando que
  ya está documentado en `requirements/README.md`, así que además actúa como
  gate: si el lock está roto, el empaquetado aborta ahí, no en el cliente.
- `actualizar.bat` FASE 4 ahora instala con
  `--no-index --find-links wheelhouse\windows-py311 --require-hashes` cuando
  el paquete trae wheelhouse, con aviso explícito y fallback a red si no lo
  trae (paquetes viejos siguen funcionando igual que antes).
